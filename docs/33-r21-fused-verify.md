# 33 — R21: Fused In-Register Verification & the Octo-Stream Fold

**Branch:** `feat/fused-vector-verify` | **Directive:** `docs/directives/04-engineer-fused-vaccum-briefing.md` | **Baseline:** `main` @ 1.959B msg/s sustained full-verify, 12.103B msg/s pure ingest

## 1. Executive Summary

This report documents the R21 program: the four engineering directives of the fused in-register verification briefing, their implementations, the algebraic proofs behind them, and the local verification evidence. The program attacks the gap between the 12.103B msg/s pure-ingest ceiling and the 1.959B msg/s sustained full-verify ceiling. That gap is dominated by two physics facts: the verification pass reads every payload byte a second time from memory (the ~62 GB/s re-read bandwidth), and the serial carryless-multiply dependency chains in the fold kernel impose a per-step latency floor that the out-of-order engine cannot hide at two chains per span. The R21 levers attack both: the octo-stream fold multiplies the independent chain count by eight, the fused verification shape eliminates the second read pass structurally, the non-temporal descriptor publications remove the warm-start copy's cache pollution, and the topology verification converts the placement from a best-effort selection into a sysfs-verified, loudly-verdicted fact on every draw.

Every lever ships behind the house-law gating (default OFF until CI certifies, or ON with a documented rollback for the levers the directive itself mandates), every value path is pinned bit-exact against the scalar kernel `span_crc32c_8lane` by the same differential machinery that certified the R13/R14/R15/R16 rounds, and the golden parity hash `0x881639cead506f25` (message population 505849, `0xF6EF154EFDE905D8` for the replay conformance verdict) is asserted unchanged in every local run of the modified stack.

## 2. Task 1 — The Octo-Stream (T=8) Fold (`crcfold.rs`, `kbench.rs`)

### 2.1 The problem and the shape

The natural-domain (reflect) fold advances its (even, odd) state pair by one 128-byte block-pair unit per step. Each step's clmul chain runs `clmul → ternlog → clmul → ternlog → next step`, so the whole loop is bounded by roughly the clmul latency chain per 128 bytes; measured fold rates sit near the chain-bound ~9 cycles/step rather than the port-5 throughput floor (~6 cycles/step). The R11 tri-stream split (mod-3 across three state pairs) and the R16 dfold split (mod-2 block parity) each deepened the ILP; the directive's Task 1 names the full shape: eight independent parallel accumulators folding concurrently before a tree reduction.

The R21 kernel (`fold_word_octets_r`) splits the span's word-pair units mod-8 across EIGHT independent (even, odd) `FoldStates` — sixteen independent clmul chains over one sequential load stream. Stream `m` folds block-pairs `{m, m+8, m+16, ...}`; between consecutive units of one stream sit seven units of the others, so each stream's step advances its state by eight units of degree. Because the R16 P1' class law identifies the step map with ring multiplication by `K = RKLO mod VM = VR0` in `GF(2)[y]/VM`, an eight-unit advance is ONE 2-clmul step with the reduced pair `(K^8 ⊗ y^64, K^8)`. After the loop, the eight stream states merge into the single-stream state: stream `m` carries offset `C_m = (wp−1−m) mod 8` units, and each merge is one 2-clmul step with the reduced pair `(K^{C_m} ⊗ y^64, K^{C_m})`. The base stream (the one owning the body's last unit) merges by identity; empty streams merge to zero. The merges are mutually independent — fourteen independent clmuls plus a three-deep XOR tree, executed once per span off the hot loop.

### 2.2 The constants and their proofs

The step pair and the seven merge pairs all reduce to the R15 G-table law: `K^k = y^(−128k) = G[16k]` and `K^k ⊗ y^64 = G[16k−8]`. The shipped tables stop at `G[71]`, so the program derives `G[72..=128]` — `scripts/r21_ofold_derive.py` extends the reflected-CRC32C table advance (the seed-1 state stepped by `(c >> 8) ^ T[c & 0xFF]`) and validates the extension three ways: the derived table reproduces the shipped `VTAIL_G[0..72]` verbatim, the inverse-powers law `G[r] ⊗ y^(8r) = 1 (mod VM)` holds at seven probes, and the class law holds on 300 random full-width states at every octo power (one reduced-pair application equals k stepwise R13 advances in class terms). Every emitted constant is ≤ 32 bits — the R16 width law that keeps the state's hi qword ≤ 33 bits and every composed ending field ≤ 96 bits, inside the vend exactness range.

The full Python differential (P2) runs the octo model through the shipped vtail ending against the scalar reference: 2178 bodies bit-exact (exhaustive lengths 192..700 across four content patterns, representative longs to 16384, and 120 random lengths), plus cross-model agreement with the R15 vtail and R16 dfold shapes on a shared battery — three independent loop structures, one value. The Rust port re-derives the entire constant table at test time (`t_ofold_constants_derivation`: the G extension, all seven merge pairs against both the ring powers and the table indices, the step pair, and the P1' octo class law on one-hot states), so a transcription typo cannot survive the suite.

### 2.3 Dispatch, endings, and attribution

The merged octo states are CLASS-exact (ring-congruent), not value-identical, to the sequential kernel's states — exactly the dfold situation — so the dispatch applies the dfold law: `vend` is forced on and the vtail composed-field lane-0 path runs for all `r` (`span_fold_eval_r_forced_o(body, vend, vtail, dfold, ofold)`; `ofold && !vend` resolves OFF; ofold preempts dfold when both arm). The env gate `HFT_CRC_OFOLD` (default OFF — the documented rollback until ≥ 3 healthy-draw verdicts certify it, the dfold precedent) rides the standard evaluation paths, so the worker loops, the pair path, and the fabric all inherit the axis without further changes. The kbench attribution row `fold512_ro` (1t, 2cpu_distinct, 2cpu_smt) prices the kernel effect against `fold512_rv` on the same draw, and CI arm 11oa soaks the armed fabric.

## 3. Task 2 — Fused Submit-Side Verification (`hydra.rs`, CI 11fb)

The fabric's sustained shape pays the second memory read pass: ingest framing produces span bodies into the blob, then worker cores re-read those bytes through the descriptor protocol to fold them. The R21 fused shape eliminates the re-read structurally: every chunk is claimed inline at submission (`HFT_INLINE_FORCE=1`, the deterministic parity configuration the fabric already ships for tests), so `submit_inline_span` evaluates each span's CRC on the submitting core at the framing point — while the span's lines are the most-recently-touched bytes of that core's cache hierarchy — and the handoff to the ordered fold degenerates to VALUES (inline-ring entries), not bytes. The workers never touch the payload; the 62 GB/s re-read bandwidth disappears from the verification path, and the descriptor/res ring traffic for inline chunks disappears with it.

This is deliberately a configuration of the existing, verified inline-assist machinery (the deep assist ring, the claim-order invariant, the sealing protocol, the fold-order assert) rather than new protocol: the per-pass bit-parity asserts and `ALLOC_DELTA == 0` run unchanged over it, and the local run confirms `HYDRA_BITPARITY ... -> BIT-EXACT` on the golden population with the fused shape armed. The `HYDRA_FUSED_DIAGNOSTIC` line (printed once per process, on the first fused-sink construction) proves the shape armed on every draw — the flip-validation law that an arm is never priced on faith. CI arm 11fb soaks it; sustained-vs-11b on the same draw prices the fused fabric shape per silicon class. The honest expectation, recorded here for the fleet to decide: on the 4-vCPU target classes the fused shape trades worker-side parallelism for eliminated memory traffic and handoff latency; the direction is an empirical per-class question, and the arm exists to answer it.

`hft_bench.rs` keeps its hash-off-hot-path contract untouched by design: its JSON gate measures PURE ingest (constr1.1), and fusing verification into that measurement window would regress the very metric it exists to keep clean. The fused-verify frontier is the hydra fabric, and that is where the lever lives.

## 4. Task 3 — 64B Compact Descriptors & Non-Temporal Publications (`rxdesc.rs`, `hydra.rs`)

The descriptor compactness invariant is now pinned at compile time in both files that own handoff structures: the array descriptor is one `u64` word (eight per 64-byte line), the legacy ring descriptor sixteen bytes, the result slot (`Res`) sixteen bytes, and the padded cursor words exactly one line — `const _: () = assert!(...)` blocks fail the build if any struct fattens toward the 128-byte shape the directive prohibits (the variant that regressed cache throughput by 115M msg/s). There is no fat-descriptor code path to remove: the invariant is now load-bearing in the type system rather than tribal.

The publication burst that DID pollute is the warm-start copy: `RxdescState::copy_arr` moves ~1 MB of descriptor array per window open (the pass boundary's synchronous bake — the F-5 telemetry measured this tail at 9.7% of the sustained wall pre-budget). The copy's cache footprint is pure pollution: the submitting core never reads the array again, and the workers' first touch is a full window later. R21 rewrites it as 64-byte non-temporal streaming stores (`_mm512_stream_si512`) over the phase-aligned middle, with scalar head/tail, a runtime AVX-512F gate, a shared-phase check that falls back to `copy_nonoverlapping` when the arrays' 64-byte phases differ, and — load-bearing for the protocol — a trailing `_mm_sfence` that orders the weakly-ordered NT stores before the subsequent `publish_record`/`publish_ready` Release stores. `HFT_NT_COPY=0` is the documented rollback; default ON, per the directive's explicit order. The per-span descriptor stores themselves (the Desc8 word writes and the chunk-close Release) stay untouched: those lines are consumed by workers immediately and WANT cache residency — streaming them would be a pessimization, and the briefing's own geometry (8 descs per line) already minimizes their line traffic.

## 5. Task 4 — Topology Verification (`affinity.rs`, `pipeline.rs`, `hft_bench.rs`)

The directive's law: the (Main Sequencer, RX Ingest Producer) pair must land on distinct physical cores sharing the same L3 domain — the shape that locks in the 0.21 cyc/msg ingest mode. Until R21 the placement was a selection heuristic with no runtime verification; the R8 mask-pollution incident (a pinned main's shrunken affinity mask collapsing a later placement to `[0, 0]`) is precisely the failure mode silent selection invites. R21 adds the verification layer:

* `verify_pair_topology(main, rx)` reads sysfs truth (never the placement's intentions) and returns a three-state `TopologyVerdict`: `Verified` (disjoint `thread_siblings_list` groups, identical `index3/shared_cpu_list`), `Violated(reason)` (same cpu, SMT siblings, or split L3 — each with a human-readable cause), or `Unverifiable(reason)` (a host without the sysfs truth cannot be held to a law it cannot express — degraded to a warning in every mode).
* `verify_pipeline_placement(...)` prints the `TOPOLOGY_VERIFICATION` verdict line into every draw log and, under `HFT_TOPOLOGY_STRICT=1`, hard-fails a violation. `hft_bench.rs` additionally verifies that the main thread's ACTUAL landing cpu (`sched_getcpu`) equals its intent — the silent `let _ = pin` failure mode can no longer hide.
* `pipeline.rs` records the RX thread's actual landing cpu into the mailbox right after its pin attempt (`rx_actual_cpu`), surfaced through the `DIAG rx` telemetry line and the `rx_actual_cpu()` getter, with an intended-vs-actual verdict line in `hft_bench.rs`; CI section 11sl greps both lines so the verdict can never go silent.
* Two new unit tests pin the predicate: a same-cpu pair is always a violation on any host, and the placement's own output is never a violation on hosts where the L3-group path actually ran (selection and verifier share the same sysfs truth — a disagreement is an internal inconsistency, and the test fails on it).

The sustained fabric reads 417M msg/s distributed vs 307M fused locally — on a 2-vCPU host the distributed shape has a spare worker core and the fused shape does not; the 4-vCPU target classes reverse that arithmetic, which is why arm 11fb exists.

## 7. Rollbacks and Certification Path

Every lever carries its knob: `HFT_CRC_OFOLD=0` (octo fold, default OFF), `HFT_NT_COPY=0` (NT warm-start copy, default ON per the directive), `HFT_INLINE_FORCE=0` (fused shape, default OFF outside the arm), `HFT_TOPOLOGY_STRICT` unset (verdicts print, nothing fails). The certification path follows the house law: ≥ 3 healthy target-class draws pricing each armed lever against its 11b control via the kbench twins (`fold512_ro` vs `fold512_rv`) and the sustained verdict lines, then the default-flip protocol. The 2.5–3.0B sustained milestone is then a fleet question: the octo fold and the fused shape are the two structural levers the briefing names, both now shipped, tested, attributable, and one CI push away from their first target-silicon evidence.
